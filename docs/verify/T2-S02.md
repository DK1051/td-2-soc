### New findings in the final review

1. **should-fix (cheap, docs only):** `2h-detection-pack/README.md:48` says: "If the command fails, the harness uses the persistent form with paths under `/kustodata`." The code has no such fallback. `kql_common.reset_database()` runs only `.create database … volatile` and has a `TODO(verify)` comment saying to switch to `persist` *if* a future image refuses it. Line 50 likewise says "or `.ingest inline` as the alternative", but the harness uses only `.set-or-append`. The README describes behaviour that does not exist, which goes against CLAUDE.md's "never invent facts", and Eojin could be asked about it in an interview. Fix: say that the harness uses `volatile` (accepted by the pinned image) and `.set-or-append`, and that `persist` / `.ingest inline` are the documented alternatives if a future image refuses them.
2. **nit:** `docs/RUN-SHEET.md` marks T2-S02 "DONE (PR #4)" before the PR exists. The REST lookup for this head branch shows only PRs #1–#3, all closed. Confirm the number once the PR is opened. The T2-S01 row still says "IN PROGRESS (PR #1 open …)", but PR #1 is closed. That row is not part of this diff, but it is stale.
3. **nit (accepted limit):** the blind-hunt guard in `run_detections.py` compares resolved paths case-sensitively. On a case-insensitive filesystem (Windows or macOS, which is where Eojin works), a spelling such as `2E-Blind-Hunt/Data` might get past it, and so would a copy of the data. It is a guard against accidents, not a security boundary. If wanted, compare `os.path.normcase` values.
4. **nit:** a cosmetic over-long line in the `false_positive_notes` block of `TD-2H-05.yaml` (around line 18). The YAML folds it correctly.
5. **Interview risk (for `class T2-S02`):** these are the parts Eojin is most likely to struggle to explain: the TD-2H-06 regex (`newValue":"([^"]*;)?\s*verified: …`), and TD-2H-04's `minif` plus `max_of(coalesce(...))`. Both have comments, but they deserve time in the lesson.
6. **Unsafe patterns:** none found. Values become KQL literals through `json.dumps` (escaped, not string concatenation). The emulator client uses `with_no_authentication` and only the local URL. `run_detections.py` prints counts only, never user names or rows, so the public CI logs stay clean. KQL that reaches other data (`cluster`, `database`, `externaldata`) is rejected by the static checker.
7. **Secrets:** none. A grep of every changed file for key, token, password, secret, private-key, AKIA/ghp_/xox/sk- and `AccountKey=` patterns found only prose ("password reset") and the existing `secrets.GITHUB_TOKEN` reference in `ci.yml`. Of strings of 32 or more characters, only the image digest is random-looking; GUID literals: none. `gitleaks` is not installed locally, so the CI `checks` job's gitleaks step is the authoritative scan.
8. **Fictional data:** every user name in the code is built as `…@mapleharbour.example`, and every UPN in the fixtures alerts file is in that domain. Synthetic IPs are in the documentation ranges 203.0.113.0/24 and 198.51.100.0/24. The people named in the README (Katya Hashemi, Uma Jovanovic) are fixture look-alikes.
